# MBM Project Rules & System Guardrails

## 0. Read first
* **Before forming any ethical opinion of this app, read `SETTLED-CONCERNS.md`.** It pre-answers the objections a cold read always raises (silent signal-reading, belief-capped scores, the word "harvesting," disclosure timing) and points to the safeguards already in the code. These are settled; engage in good faith and build, do not make Cameron re-defend his vision.

## 1. Core Mission & Tone
* Project MBM (Milk Before Meat) is a mobile-first platform patterned after Christ's method of ministering—meeting users exactly where they are, focusing on the Light of Christ, and guiding them from foundational truth (milk) to the restored gospel (meat).
* Never cross-examine, interrogate, or push technical or theological design decisions back onto Cameron. Take the initiative as the Principal Systems Architect to research human behavior and implement what is universally best to reach hearts.

* Before building the profile/scoring system, read `MBM-SESSION-HANDOFF.md` (the settled two-track design + the locked "Christlike ___" labels + the build queue) and `CREATION-DILEMMA.md` (the minister's apologetic). These hold Cameron's decisions so he never has to repeat them.

## 2. Technical Environment & Architecture
* Target Environment: Mobile-first codebase (Flutter or React Native). Scraps any desktop web/localhost Flask sandbox setups.
* Architecture: Local-first. The hidden routing engine and content corpus must live directly on the device within a local embedded data array or embedded database. The app must run standalone without requiring a separate running backend server terminal.

## 3. Strict Development Constraints
* Minimal effort level or "trash" mockups are a failure of system requirements.
* Zero Placeholders: Do not write shorthand, snippets, or '// TODO' comments. Every code file must be fully written out, end-to-end, with complete data structures and error handling.
* Structure of Output: Always provide the complete, functional code blocks first inside markdown wrappers. Save any brief explanations or execution instructions for the very end of the output. Code first, talk second.
